## Purpose and Scope

The solution manages rental request intake, approval, contract activation,
monitoring, extension, cancellation, pickup, inspection, damage review, and
closure. It is a capability showcase, not a production ERP replacement.

## Solution Architecture

Maestro Case owns lifecycle state, stages, human tasks, exceptions, SLAs, and
case history. Data Fabric is the shared system of record. API Workflows own
deterministic reads, writes, monitoring, and mock-vendor integration. RPA is a
limited UI-only fallback. Python Agent and Agent provide advisory capabilities;
they cannot directly commit financial or lifecycle state.

## Case Design

Primary stages: Intake, Approval, Fulfillment, Active Monitoring,
Disposition, and Closure. Secondary stages: Extension Review, Cancellation
Review, Return/Pickup Coordination, Damage Review, Overdue Escalation, and
Exception Recovery.

Human tasks cover approvals, extension approval when required, damage-charge
approval, and exception resolution. The case must only close after return is
confirmed and any required damage review is complete.

## Integration Design

- Vendor 1: API-first availability, booking, cancellation, and pickup.
- Vendor 2: API with delayed confirmation event.
- Vendor 3: mock portal used solely by the RPA fallback path.
- All vendor callbacks require unique `source_event_id` values.

## Security and Governance

Use the shared release folder `EquipmentRENTAL/LCversion`, least-privilege
roles, managed connections, and approved tools. Agent tools are restricted to
the API workflows; they cannot perform unreviewed direct mutations. Case roles
are process-scoped.

## Runtime and Deployment

API workflows and agents use serverless services. The RPA project is a
background cross-platform process only when serverless eligibility is verified;
otherwise it uses an approved unattended runtime. The final solution is packed
and deployed as one `.uipx` solution.

## Testing Strategy

Execute `docs/plans/test-spec-equipment-rental-uipath-solution.md` through
UiPath Test Manager. Cover happy path, monitoring, extension, cancellation,
immediate pickup, return/damage, overdue, agent guardrails, RPA fallback,
idempotency, and correlation integrity.

## Risks and Assumptions

- RPA runtime eligibility is confirmed during preflight before project build.
- Vendor systems are controlled mock integrations; their contracts are owned
  by the API workflow workstream.
- The business defaults in the PRD are showcase assumptions.
